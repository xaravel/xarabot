# Glossary

- **Unit:** one piece of work a lane takes: a Story, a retro, a retro action item, a planning step, or a checkpoint record.
- **Lane:** one long-running worker on a host, with its own worktree, state folder, scheduled job, agent and model.
- **Coordinator lane (lane 0):** the only lane that runs retros, retro action items and planning, and the only writer of `sprint-status.yaml` and `retro-gates.yaml`.
- **Builder lane (lanes 1..N):** a lane that builds Stories only.
- **Claim:** a lane's exclusive hold on a unit, made by compare-and-swap on a git ref, kept alive by heartbeat, expiring 30 minutes after the last heartbeat.
- **Story manifest:** the per-Story record in the consuming repo that gives the Story's path globs (directly, or through a repo mapping such as Xaravel's `component`) and its dependencies. Claims and the guard use its globs. Its format is spine AD-10.
- **Epic graph file (`.xarabot/epics.yaml`):** the consuming repo's record of each Epic's dependencies and checkpoint. An Epic it does not list depends on the next lower Epic number in `epics.md`; a checkpoint is never inferred. It is Xarabot config, so a Protected Path: a change to it, or to the Epic headings or a manifest's Epic, merges only with the Maintainer's approval.
- **`next`:** the command that returns the one unit a lane builds next.
- **Adapter:** the code that runs one vendor's agent CLI for a unit and returns its JSON result.
- **Checkpoint Epic:** an Epic after whose retrospective the Maintainer must say "go" before the Epics that depend on it, directly or through others, start; Epics not depending on it keep running (Xaravel: Epic 8).
- **Retro gate:** the record of an Epic's retrospective verdict and its open action items (`retro-gates.yaml`).
- **Blocking action item:** a retro action item tagged `blocking`. It holds back every Epic depending on its Epic; an untagged open item holds back only Epics two or more dependency steps away (CAP-10).
- **Write check:** the 0.x runner check that refuses a builder diff touching coordinator-owned files, manifests, agent config or Protected Paths before the squash (CAP-18).
- **Inbox:** the single list of everything waiting on one human. Each owner has one; the Maintainer's also holds rulings, Escalations, retro items and Human Live Steps.
- **Maintainer:** the human who owns the consuming repo's rulings, Protected Paths and releases.
- **Protected Path:** a path in the consuming repo that changes only through a Maintainer-approved Infrastructure Story (Xaravel AD-16), or, for the Epic graph file, a Maintainer-approved planning PR.
- **Infrastructure Story:** a Story that changes Protected Paths, approved by the Maintainer before a lane builds it.
- **Escalation:** a question an agent raises instead of deciding a contract matter. A human decision binds to its exact text by hash, and an open Escalation blocks its unit's merge (CAP-20).
- **Lesson:** a cross-Epic lesson recorded from a retrospective (Xaravel: `lessons.md`), injected into later sessions (CAP-21).
- **Standing Authority file:** the consuming-repo file that grants the lanes their authority; when it is absent or invalid, every lane stops (CAP-22). Xaravel's MAINT decision file is its Standing Authority file.
- **Human Live Step:** a step only a human performs, such as changing live GitHub settings, secrets or rulesets. Lanes never attempt one (CAP-23).
- **Actor registry:** the consuming-repo record of humans by GitHub login, their roles and tracks, and the bot each owns (CAP-17).
- **Role and track:** how the Actor registry groups humans: a role sets a human's rights, a track the stream of work they belong to. The consuming repo defines both.
- **Bot (`<login>-xarabot`):** the GitHub App one human's account owns, acting as `<login>-xarabot[bot]`. All of that human's lanes commit, push and open PRs as it. It is installed once per consuming org with the org owner's approval, on all repositories by default, has no admin, bypass or approve rights, and works through hourly tokens the runner mints from its private key.
- **`xarabot join`:** the package command that creates a human's bot App from a manifest, stores its private key for the runner, and installs it or requests the install.
- **Owner:** the human a bot belongs to. Their review makes the bot's Protected Path PRs mergeable.
- **STOP marker:** the file that makes a lane, or every lane on a host, exit after its current unit.
- **Forge adapter:** the code that connects lanes to one forge for identity, PRs, CI, merges and claims: GitHub (0.x), local-only (v1).
- **Local-only mode:** Xarabot on a repo with no remote, on one host; merges go to the local `main`, and approvals are signed with the owner's key.
- **Xarabot host:** the computer a person's lanes run on, set in config (`XARABOT_HOST`): any macOS or Linux machine, usually not the operator's own.
